# v0.1.0 Context Switch Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove a real x86_64 kernel-task context switch with an independent stack, two round trips back to the bootstrap task, and no regression in the existing Ring 3/syscall probe.

**Architecture:** Keep policy in `crates/kernel` and privileged register/stack manipulation in `crates/arch`. The architecture layer will represent a saved context by its stack pointer, save/restore callee-saved registers in assembly, and provide a helper that prepares a fresh stack so the first restore enters a supplied function. The kernel will allocate one physical frame for a worker stack from the same `FrameAllocator` later used by the Ring 3 probe, perform two cooperative switches, emit serial evidence, then continue into the existing userspace probe.

**Tech Stack:** Rust `no_std`, x86_64 assembly, bootloader 0.11.10, QEMU/OVMF, GitHub Actions.

**Spec:** `docs/roadmap.md` (`v0.1.0` context-switch and kernel-stack requirements)

## Global Constraints

- Safe Rust remains the default; raw stack/register manipulation stays in `crates/arch`.
- Do not claim preemptive multi-task execution from this slice; this is a cooperative context-switch foundation.
- Existing `Ring 3 -> int 0x80 -> kernel -> Ring 3 -> int3` smoke evidence must remain green.
- Use the existing physical-memory allocator; do not add a second allocator or dynamic VM subsystem.
- CI must require runtime evidence for the new switch path before documentation can call it implemented.

**Files:**

**Interfaces:**

- Produces: `pub unsafe fn switch(current: &mut Context, next: &Context)`

- [ ] **Step 1: Write the failing stack-layout test**

Add a host test that prepares a 4 KiB aligned byte buffer and verifies the resulting saved stack pointer is 16-byte aligned, lies inside the buffer, and encodes the expected initial callee-saved/register/trampoline frame.

- [ ] **Step 2: Run CI and verify RED**

Open a draft PR so the existing `pull_request` workflow runs. Expected: host tests or compilation fail because the context preparation API is not implemented yet.

- [ ] **Step 3: Implement the minimal context preparation and switch mechanism**

Use the saved-stack layout:

```text
saved RSP -> r15
             r14
             r13
             r12 = argument
             rbx
             rbp
             return address = context trampoline
```

The trampoline moves `r12` into the SysV first argument register and invokes `entry`; the entry is non-returning.

The switch path must save and restore exactly the same callee-saved register sequence and save the current `rsp` through `Context.stack_pointer`.

- [ ] **Step 4: Re-run CI and verify GREEN for host tests/check/clippy/build**

Expected: the new unit test passes, existing tests stay green, and the target kernel still builds.

### Task 2: Prove two cooperative round trips on an independent kernel stack

**Files:**
- Modify: `crates/kernel/src/lib.rs`
- Modify: `.github/workflows/ci.yml`

**Interfaces:**
- Consumes: `nastalli_arch::context::{Context, prepare, switch}`
- Produces runtime markers:
  - `Context switch: worker entered.`
  - `Context switch: bootstrap resumed.`
  - `Context switch: worker resumed.`
  - `Context switch: bootstrap resumed twice.`

- [ ] **Step 1: Add the failing QEMU smoke assertions**

Add `grep -F` checks for all four markers before the existing Ring 3/syscall markers.

- [ ] **Step 2: Run CI and verify RED**

Expected: compile/unit checks remain green but QEMU smoke fails because the markers do not exist yet.

- [ ] **Step 3: Refactor startup to own one `FrameAllocator`**

Create one allocator in `start()` after memory reporting and pass `&mut FrameAllocator` to both the context-switch probe and `prepare_ring3_probe()`. This prevents duplicate allocation of the same usable frames.

- [ ] **Step 4: Implement the worker-stack probe**

Allocate one physical frame, convert it through `physical_memory_offset` to its direct-mapped writable virtual address, zero it, prepare a worker context, and perform two bootstrap/worker round trips. Keep the small shared probe state at a stable heap address so the worker can update its own saved context and switch back safely.

- [ ] **Step 5: Re-run CI and verify GREEN**

Expected QEMU order:

```text
Context switch: worker entered.
Context switch: bootstrap resumed.
Context switch: worker resumed.
Context switch: bootstrap resumed twice.
Ring 3 syscall entered kernel and returned.
Ring 3 probe reached kernel breakpoint.
```

# v0.1.0 IRQ-Driven Preemption Foundation Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Prove repeatable IRQ0-driven switching between two Ring 0 tasks without either task voluntarily yielding.

**Architecture:** Add a raw x86_64 timer entry that saves all general-purpose registers above the CPU-created `RIP/CS/RFLAGS` frame, calls a narrow interrupt-safe dispatch hook, switches `rsp` to the scheduler-selected saved frame, restores registers, and returns with `iretq`. Keep the existing cooperative context format separate because its frame is not an interrupt frame. Restrict the first proof to Ring 0 tasks sharing the current address space and uninstall the preemption hook before entering the Ring 3 validation path.

**Tech Stack:** Rust `no_std`, x86_64 `global_asm!`, legacy PIC/PIT, QEMU/OVMF, GitHub Actions.

**Spec:** `docs/roadmap.md` (`v0.1.0` IRQ-driven preemption target)

## Global Constraints

- Development changes land directly on `main`; no feature branches are created for this slice.
- Every committed state must include implementation and tests together rather than intentionally breaking `main` for a RED commit.
- Scheduler policy remains in `crates/kernel`; raw interrupt/register mechanisms remain in `crates/arch`.
- Do not call the existing cooperative `context::switch` from IRQ0.
- Do not claim Ring 3 preemption, FPU/SIMD context switching, SMP safety, process isolation, or production scheduling from this slice.
- The Ring 3 syscall/breakpoint smoke path must remain green after the preemption proof.

### Task 4: Prove non-cooperative IRQ switching under QEMU

**Files:**
- Modify: `crates/kernel/src/lib.rs`
- Modify: `.github/workflows/ci.yml`

**Runtime proof:**

```text
bootstrap --IRQ0--> worker --IRQ0--> bootstrap --IRQ0--> worker --IRQ0--> bootstrap
```

The worker must never call scheduler/yield APIs. It only increments an atomic heartbeat.

Required smoke markers:

```text
Preemption: worker executed without yielding.
Preemption: four IRQ-driven task switches observed.
Preemption: bootstrap resumed twice.
Ring 3 syscall entered kernel and returned.
Ring 3 probe reached kernel breakpoint.
```

- [ ] Install the hook only after scheduler/worker setup.
- [ ] Use a bounded tick timeout so a failed proof produces a kernel panic rather than an unbounded silent loop.
- [ ] Clear the hook before entering Ring 3 because this first frame format is Ring-0-only.
- [ ] Require all old privilege-boundary smoke evidence after the new preemption markers.
